# 领域通用化使用指南

## 概述

系统已实现领域通用化改造，支持多个行业领域的面试场景，无需修改代码即可扩展到新的行业领域。

## 已支持的领域

目前系统内置了以下三个领域：

| 领域ID | 领域名称 | 适用行业 | 典型岗位 |
|--------|----------|----------|----------|
| `tech` | 技术/互联网 | 软件开发、IT、人工智能、云计算 | 软件工程师、架构师、产品经理 |
| `marketing` | 营销/传媒 | 广告、公关、新媒体、品牌咨询 | 营销经理、品牌专员、内容运营 |
| `healthcare` | 医疗/护理 | 医院、诊所、护理中心、康复机构 | 护士、护理主管、健康管理师 |

## 使用方法

### 1. 在面试引擎中指定领域

```python
from core.interview_engine import InterviewEngine

engine = InterviewEngine()

# 使用tech领域（默认）
result = engine.run_interview(
    job_file="senior_backend",
    company_file="tech_startup",
    candidate_config=candidate_config,
    domain_id="tech"  # 可选，默认为tech
)

# 使用marketing领域
result = engine.run_interview(
    job_file="marketing_manager",
    company_file="marketing_agency",
    candidate_config=candidate_config,
    domain_id="marketing"
)

# 使用healthcare领域
result = engine.run_interview(
    job_file="registered_nurse",
    company_file="general_hospital",
    candidate_config=candidate_config,
    domain_id="healthcare"
)
```

### 2. 在随机生成器中指定领域

### 3. 直接使用DomainLoader

```python
from domains import DomainLoader, list_available_domains

# 列出所有可用领域
domains = list_available_domains()
print(domains)  # ['healthcare', 'marketing', 'tech']

# 加载特定领域
domain = DomainLoader("marketing")

# 获取领域配置
config = domain.get_domain_config()
print(config['domain_name'])  # '营销/传媒'

# 获取技能分类
taxonomy = domain.get_skills_taxonomy()
categories = domain.get_skill_categories()

# 获取评估信号
high_level_terms = domain.get_high_level_terms()  # 高级专业术语
vague_words = domain.get_vague_words()  # 模糊词汇
weakness_indicators = domain.get_weakness_indicators()  # 露怯关键词
```


## 配置文件说明

### domain_config.json
定义领域的基本信息和元数据。

### skills_taxonomy.json
定义该领域的技能分类体系，包括：
- **skill_categories**: 硬技能分类（如backend、frontend、clinical等）
- **soft_skills**: 软技能定义
- **skill_descriptions**: 技能详细描述（可选）

### assessment_signals.json
定义面试评估使用的信号词汇，用于：
- 检测候选人是否不懂装懂
- 识别实战经验证据
- 发现模糊回答和露怯信号

### question_templates.json
定义问题生成模板，支持：
- 按技能水平分级（basic/intermediate/advanced）
- 追问模板（probe_depth/challenge_weakness/verify_experience）
- 场景化问题

## 向后兼容性

- 如果不指定 `domain_id` 参数，系统默认使用 `"tech"` 领域
- 所有现有代码和测试无需修改即可正常运行
- 领域配置完全独立，互不影响

## 技术细节

### 领域配置加载优先级

```
用户指定domain_id > 默认tech领域 > 自动降级
```

### 配置缓存

DomainLoader 会缓存已加载的配置文件，重复调用不会重新读取文件。

### 错误处理

- 如果指定的领域不存在，自动降级到 `tech` 领域并记录警告
- 如果配置文件格式错误，返回空字典并记录错误日志

## 最佳实践

1. **命名规范**: 领域ID使用小写字母，单词间用下划线（如 `data_science`）
2. **术语选择**: 高级术语应选择该领域的核心专业概念，避免过于基础或过于宽泛
3. **技能分类**: 每个类别包含3-8个技能为宜，不要过多或过少
4. **模板设计**: 问题模板应具有通用性，使用占位符 `{skill}` 等
5. **持续迭代**: 根据实际面试反馈不断优化信号词汇和问题模板

## 常见问题

### Q: 如何判断应该添加新领域还是复用现有领域？
A: 如果技能体系、评估标准、专业术语差异明显，建议创建新领域。如果只是岗位不同但技能相似，可以复用现有领域。

### Q: 一个领域可以用于多个岗位吗？
A: 可以。领域定义的是行业特性，具体岗位通过 `job_config` 定义。例如 `tech` 领域可用于前端工程师、后端工程师、架构师等多个岗位。

### Q: 如何修改现有领域的配置？
A: 直接编辑 `domains/{domain_id}/` 下的JSON配置文件即可，无需修改代码。

### Q: 配置文件编码要求？
A: 所有JSON文件必须使用UTF-8编码，支持中文。
