# 域配置 - 切换域问题修复说明

## 🐛 问题描述

在"现有域管理"中，切换不同的域时：
- ✅ **技能体系Tab** - 内容能正常切换
- ❌ **基本信息Tab** - 内容不会自动改变
- ❌ **问题模板Tab** - 内容不会自动改变  
- ❌ **评估信号Tab** - 内容不会自动改变

## 🔍 根本原因

### Streamlit组件的key机制问题

Streamlit的输入组件（`st.text_input`, `st.text_area`等）使用`key`参数来标识和管理组件状态。关键机制：

1. **相同key = 保持状态**：如果key不变，即使`value`参数改变，Streamlit也会保持用户已输入的内容
2. **不同key = 重新渲染**：如果key改变，组件会使用新的`value`重新渲染

### 代码对比

**❌ 问题代码（基本信息Tab）**
```python
domain_name = st.text_input(
    "领域名称*",
    value=config.get('domain_name', ''),  # value会变
    key="domain_name"  # ⚠️ key固定不变
)
```

当从tech切换到marketing时：
- `value`参数从"技术"变成"营销"
- 但`key="domain_name"`保持不变
- Streamlit认为这是**同一个组件**，保持旧内容"技术"

**✅ 正确代码（技能体系Tab）**
```python
cat_name = st.text_input(
    "分类名称",
    value=cat_data.get('name', ''),
    key=f"cat_name_{cat_id}"  # ✅ key包含cat_id，每个分类不同
)
```

当从tech切换到marketing时：
- tech的分类ID是`backend`, `frontend`等
- marketing的分类ID是不同的
- key从`cat_name_backend`变成`cat_name_marketing_strategy`等
- Streamlit认为这是**不同的组件**，使用新value重新渲染

## ✅ 修复方案

### 核心思路

给所有输入组件的`key`添加**当前域ID**作为后缀，使得切换域时key会改变。

### 实现方法

```python
# 1. 在每个Tab函数开始时获取当前域ID
def render_basic_info_tab(config: Dict):
    # 获取当前域ID作为key后缀
    domain_key = config.get('domain_id', '') or st.session_state.get('current_domain_id', 'new')
    
    # 2. 所有输入组件的key都添加域ID后缀
    domain_name = st.text_input(
        "领域名称*",
        value=config.get('domain_name', ''),
        key=f"domain_name_{domain_key}"  # ✅ 动态key
    )
```

### 修复效果

**切换前（tech域）**
```
key="domain_name_tech"  value="技术"
key="description_tech"  value="技术领域涵盖..."
```

**切换后（marketing域）**
```
key="domain_name_marketing"  value="营销"  ← key改变，强制重新渲染
key="description_marketing"  value="营销领域..."  ← key改变，强制重新渲染
```

## 💡 设计原则

### 为什么技能体系Tab一开始就是对的？

```python
# 技能体系Tab使用的是cat_id作为key的一部分
key=f"cat_name_{cat_id}"
```

- `cat_id`在不同域中是不同的（如tech的`backend`与marketing的`digital_marketing`）
- 所以切换域时，key自然就不同了
- 这个设计无意中遵循了正确的模式

### 通用原则

**当组件内容需要随外部状态（如当前选择的域）变化时：**
1. 将该状态（域ID）纳入key的组成部分
2. 确保状态改变时，key也会改变
3. Streamlit会自动使用新的value重新渲染组件
