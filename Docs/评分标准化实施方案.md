## 🎯 问题诊断

### 当前系统的关键问题

1. **评分缺乏标准化** - 不同候选人的分数难以横向对比
2. **纯LLM主观评分** - 受模型偏差、温度参数影响大
3. **缺少校准机制** - 无法保证评分的一致性和可靠性
4. **追问机制定位模糊** - 本应是"知识盲区探测器"，而非"评分修正器"

### 追问机制重新定位

**正确定位**：
- ✅ 追问 = 知识盲区探测器
- ✅ 目标：验证候选人在特定领域的真实深度
- ✅ 结果：暴露"不懂装懂"或"过度谦虚"

**错误定位**：
- ❌ 追问 = 评分修正器
- ❌ 依赖追问来"修正"不准确的初始评分

## 🔬 学术界最佳实践

### 方案1：LLM-Rubric框架（强烈推荐）⭐⭐⭐⭐⭐

**来源**: Microsoft Research, ACL 2025  
**GitHub**: https://github.com/microsoft/LLM-Rubric  
**论文**: https://arxiv.org/abs/2501.00274

#### 核心思想

```
多维度问题 + LLM评估 + 校准网络 = 标准化评分
```

#### 关键创新

1. **多维度评分Rubric**：不问"表现如何"，而问6-8个具体维度的问题
2. **LLM逐维度评估**：对每个维度分别评分（1-4分）
3. **神经网络校准**：训练小型MLP将LLM评分映射到标准化分数
4. **个性化校准**：可以针对不同"评委"风格进行校准

#### 效果

- R² = 0.75（解释75%的评分方差）
- 大幅优于直接LLM评分（R² ≈ 0.05）

---

### 方案2：G-Eval + Token概率归一化 ⭐⭐⭐⭐

**来源**: "G-Eval: NLG Evaluation using GPT-4" (2023)  
**开源实现**: https://github.com/confident-ai/deepeval

#### 核心思想

```
不只看LLM输出的数字，还要看生成这个数字的token概率分布
```

#### 工作原理

传统方法：
```
LLM输出 → "8" → 8分
问题：不稳定，5次可能得到 8,7,8,9,7
```

G-Eval方法：
```
LLM输出 → {1:0.02, 2:0.05, 3:0.15, 4:0.28, 5:0.30, 6:0.15, 7:0.05}
加权求和 → 4.73分（连续分数）
```

#### 效果

- 减少评分标准差：从0.8降到0.2
- Spearman相关系数：0.514（与人类评分）
- 提供不确定性信息

---

### 方案3：多评委集成 + 投票/平均 ⭐⭐⭐

#### 策略

1. **多轮评估**：同一回答评估3-5次
2. **参数扰动**：每轮使用略微不同的temperature
3. **结果聚合**：
   - 平均值
   - 中位数（推荐，对异常值稳健）
   - 去极值平均

#### 效果

- 提高稳定性
- 实施简单
- 计算成本增加3-5倍

#### 1.2 标准化评分转换

**新增文件**: `core/score_normalizer.py`

实现评分标准化器：

**功能**：
1. 将多维度评分(1-4)转换为标准化总分(0-100)
2. 应用正态分布映射（均值50，标准差15）
3. 支持Z-score标准化（需历史数据）

**核心方法**：

```python
def normalize_dimension_scores(self, dim_scores: Dict[str, int]) -> float:
    """
    输入: {"technical_depth": 3, "practical_experience": 2, ...}
    输出: 52.3 (标准化分数)
    """
    # 1. 加权求和
    weights = {
        "technical_depth": 0.25,
        "practical_experience": 0.20,
        "answer_specificity": 0.20,
        "logical_clarity": 0.15,
        "honesty": 0.15,
        "communication": 0.05
    }
    weighted_sum = sum(dim_scores[dim] * weights[dim] for dim in weights)
    
    # 2. 映射到0-100
    raw_score = (weighted_sum - 1) / 3 * 100
    
    # 3. 正态分布调整
    normalized = apply_normal_curve(raw_score, mean=50, std=15)
    
    return normalized
```

#### 3.2 校准网络训练

**新增文件**: `core/calibration_network.py`

```python
import torch
import torch.nn as nn

class CalibrationNetwork(nn.Module):
    """
    校准网络：将LLM多维度评分校准为标准化分数
    
    架构:
        Input: [6] (6个维度评分)
        Hidden: [6] -> [64] -> [64]
        Output: [1] (校准后分数 0-100)
    """
    def __init__(self, num_dimensions=6, hidden_size=64):
        super().__init__()
        self.fc1 = nn.Linear(num_dimensions, hidden_size)
        self.fc2 = nn.Linear(hidden_size, hidden_size)
        self.fc3 = nn.Linear(hidden_size, 1)
        self.relu = nn.ReLU()
        self.sigmoid = nn.Sigmoid()
    
    def forward(self, dim_scores):
        """
        Args:
            dim_scores: [batch, 6] - LLM维度评分
        Returns:
            [batch, 1] - 校准后分数 (0-100)
        """
        x = self.relu(self.fc1(dim_scores))
        x = self.relu(self.fc2(x))
        x = self.sigmoid(self.fc3(x)) * 100
        return x

def train_calibration_network(
    train_data: List[Dict],
    val_data: List[Dict],
    epochs: int = 100
):
    """
    训练校准网络
    
    Args:
        train_data: 训练数据（LLM评分 + 人类评分）
        val_data: 验证数据
        epochs: 训练轮数
    """
    model = CalibrationNetwork()
    optimizer = torch.optim.Adam(model.parameters(), lr=0.001)
    criterion = nn.MSELoss()
    
    best_val_loss = float('inf')
    
    for epoch in range(epochs):
        # 训练
        model.train()
        train_loss = 0
        for batch in train_data:
            llm_scores = torch.tensor(batch['llm_scores'])
            human_score = torch.tensor([batch['human_score']])
            
            pred = model(llm_scores)
            loss = criterion(pred, human_score)
            
            optimizer.zero_grad()
            loss.backward()
            optimizer.step()
            
            train_loss += loss.item()
        
        # 验证
        model.eval()
        val_loss = evaluate_model(model, val_data, criterion)
        
        # 早停
        if val_loss < best_val_loss:
            best_val_loss = val_loss
            torch.save(model.state_dict(), 'best_calibration_model.pt')
        
        if epoch % 10 == 0:
            print(f"Epoch {epoch}: Train Loss={train_loss:.4f}, Val Loss={val_loss:.4f}")
    
    return model
```

## 📊 评分标准建议

### 推荐：50分中心的正态分布


### 为什么选择50分中心？

**优势**:
1. ✅ 符合统计学的正态分布假设
2. ✅ 避免"60分及格"的心理锚定效应
3. ✅ 区分度更好，便于排序
4. ✅ 国际通用标准（标准分数）

**对比传统100分制**:

| 分数体系 | 及格线 | 中位数 | 区分度 | 心理负担 |
|---------|-------|-------|-------|---------|
| 传统100分 | 60 | 70-80 | 低 | 高（不及格=失败） |
| 50分中心 | 40-50 | 50 | 高 | 低（50分=平均水平） |

## 🔄 迭代与维护

### 持续改进策略

1. **数据积累**: 每次面试保存评分数据
2. **定期校准**: 每收集50个样本，重新训练校准网络
3. **A/B测试**: 对比不同评分方法的效果
4. **人工验证**: 定期抽查LLM评分与人类评分的一致性

### 评估指标

- **一致性**: 多轮评估的标准差
- **准确性**: 与人类评分的相关系数
- **区分度**: 不同水平候选人的分数分布
- **稳定性**: 同一候选人重复评估的分数方差

## 💡 关键洞察总结

1. **追问≠评分修正**
   - 追问是探测知识盲区的工具
   - 不应依赖追问来修正不准确的评分
   - 应该从根本上提高初次评分的准确性

2. **多维度>单一分数**
   - 技术深度、实践经验、诚实度等应分开评估
   - 单一总分容易掩盖问题
   - 多维度便于诊断和改进

3. **标准化是核心**
   - 50分中心的正态分布比"60分及格"更科学
   - 支持跨候选人、跨时间的公平对比
   - 符合统计学原理

4. **LLM+规则混合**
   - 纯LLM评分不够稳定
   - 需要统计方法（归一化、集成）
   - 需要校准机制（训练数据）

5. **渐进式实施**
   - 先实现简单有效的改进（多维度+标准化）
   - 再逐步引入高级方法（G-Eval、校准网络）
   - 根据实际效果调整优先级
