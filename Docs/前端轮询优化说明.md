# 前端轮询优化说明

## 问题描述

### 问题1：Favicon 不断刷新
- **现象**：页面右上角的 favicon.png 每 500ms 刷新一次
- **影响**：页面闪烁、CPU 占用高、用户体验差

### 问题2：批量模拟状态显示错误
- **现象**：批量模拟时，第一个面试结束后，前端显示"面试状态: ⚪ 空闲"
- **影响**：用户无法看到后续面试进行中，误以为系统已停止

### 问题3：候选人信息卡片内容不完整
- **缺失**：未显示技能平均分和应聘职位名称
- **影响**：无法快速了解候选人整体水平

## 根本原因分析

### 原因1：全局页面刷新
```python
# 优化前 - 每 500ms 强制刷新整个页面
if st.session_state.interview_running:
    # ... 处理消息 ...
    time.sleep(0.5)
    st.rerun()  # ⚠️ 重新运行整个 Streamlit 应用
```

**问题：**
- `st.rerun()` 会重新执行整个脚本
- 所有组件重新渲染
- Favicon、CSS、资源全部重新加载
- 造成页面闪烁和高 CPU 占用

### 原因2：批量模式下的状态管理
- 没有独立的批量进度追踪变量
- `interview_running` 在第一个面试结束后就被设置为 False
- 缺少 `batch_current` 和 `batch_total` 状态

### 原因3：职位信息未传递
- 职位名称只在 `InterviewController` 内部使用
- 未通过 session_state 传递到前端显示

## 解决方案

### 方案1：优化轮询机制（已实施）

**改进点：**
1. **增加轮询间隔**：从检查 1 次改为最多检查 5 次（2.5 秒）
2. **智能刷新**：只有在真正有新消息时才 `st.rerun()`
3. **批处理消息**：一次轮询处理所有待处理消息

```python
# 优化后
has_new_message = False
check_count = 0
max_checks = 5  # 最多检查5次，相当于2.5秒

while check_count < max_checks:
    msg = st.session_state.controller.get_message()
    if msg is None:
        check_count += 1
        time.sleep(0.5)
        continue
    
    has_new_message = True
    check_count = 0  # 发现消息，重置计数器
    # ... 处理消息 ...

# 只在有新消息时才刷新
if has_new_message or not st.session_state.controller.is_running:
    st.rerun()
```

**效果：**
- ✅ 刷新频率降低 80%（从 500ms 到 2.5s）
- ✅ 有消息时立即刷新（响应性不变）
- ✅ Favicon 闪烁大幅减少

### 方案2：批量进度追踪（已实施）

**新增 session_state 变量：**
```python
if 'batch_total' not in st.session_state:
    st.session_state.batch_total = 0
if 'batch_current' not in st.session_state:
    st.session_state.batch_current = 0
if 'all_reports' not in st.session_state:
    st.session_state.all_reports = []
```

**新增消息类型：**
```python
# InterviewController 发送批量进度
self.message_queue.put({
    "type": "batch_progress",
    "content": {
        "current": idx,
        "total": total_candidates
    }
})

# 清空之前面试的消息
self.message_queue.put({
    "type": "clear_messages",
    "content": {}
})
```

**前端处理：**
```python
if msg_type == 'batch_progress':
    progress_data = msg.get('content', {})
    st.session_state.batch_current = progress_data.get('current', 0)
    st.session_state.batch_total = progress_data.get('total', 0)

elif msg_type == 'clear_messages':
    st.session_state.messages = []
    st.session_state.final_report = None
```

**效果：**
- ✅ 实时显示批量进度（如 "2/5"）
- ✅ 状态准确显示为 "🟢 运行中"
- ✅ 自动清空上一个面试的消息

### 方案3：完善候选人信息卡片（已实施）

**新增显示内容：**
```python
# 计算技能平均分
skills = info.get('skills', {})
avg_skill = sum(skills.values()) / len(skills) if skills else 0

# 获取岗位名称
job_title = st.session_state.job_title or '未知职位'

# 显示在卡片中
st.markdown(f"""
<div class="candidate-card">
    <h3>👤 {info.get('name', '未知')}</h3>
    <p><strong>💼 应聘职位:</strong> {job_title}</p>
    <p><strong>📊 技能数量:</strong> {len(skills)} 项</p>
    <p><strong>⭐ 技能平均:</strong> {avg_skill:.1f}/10</p>
</div>
""", unsafe_allow_html=True)
```

**效果：**
- ✅ 显示应聘职位名称
- ✅ 显示技能平均分（0-10）
- ✅ 更直观的候选人概览

### 方案4：侧边栏批量进度显示（已实施）

**新增进度条：**
```python
# 批量进度
if st.session_state.batch_total > 1:
    st.markdown(f"**批量进度:** {st.session_state.batch_current}/{st.session_state.batch_total}")
    if st.session_state.batch_current > 0:
        progress = st.session_state.batch_current / st.session_state.batch_total
        st.progress(progress)
```

**效果：**
- ✅ 可视化批量进度
- ✅ 清晰显示当前/总数
- ✅ 进度条实时更新

## 技术细节

### 消息队列机制
```
InterviewController (后台线程)
    ↓ message_queue.put()
消息队列 (Queue)
    ↓ get_message()
Streamlit 前端 (主线程)
    ↓ session_state
页面渲染
```

### 轮询策略
```
开始轮询
    ↓
检查消息队列 (最多5次)
    ├─ 有消息 → 处理 → 重置计数器 → 继续检查
    └─ 无消息 → 等待500ms → 计数器+1 → 继续检查
        ↓
检查是否有新消息或状态变化
    ├─ 是 → st.rerun() 刷新页面
    └─ 否 → 不刷新
```

### 批量模式流程
```
用户点击"开始面试" (batch_size=3)
    ↓
生成 3 个候选人配置
    ↓
启动 InterviewController
    ↓
┌─────────────────────┐
│ 候选人 1            │
│  - batch_progress   │ → 更新前端 batch_current=1
│  - candidate_info   │ → 显示候选人信息
│  - interview        │ → 进行面试
│  - final_report     │ → 显示报告
│  - clear_messages   │ → 清空消息
├─────────────────────┤
│ 候选人 2            │
│  - batch_progress   │ → 更新前端 batch_current=2
│  - candidate_info   │ → 显示新候选人
│  - interview        │ → 进行面试
│  - final_report     │ → 显示报告
│  - clear_messages   │ → 清空消息
├─────────────────────┤
│ 候选人 3            │
│  - batch_progress   │ → 更新前端 batch_current=3
│  - candidate_info   │ → 显示新候选人
│  - interview        │ → 进行面试
│  - final_report     │ → 显示报告
└─────────────────────┘
    ↓
所有面试完成
    ↓
interview_running = False
```

## 未来改进方向

### 可能的优化
1. **WebSocket 实时通信**：替代轮询机制，实现真正的推送
2. **增量渲染**：使用 `st.empty()` 容器进行更细粒度的局部更新
3. **消息缓冲**：积累多条消息后一次性更新，进一步减少刷新
4. **进度估算**：预估每个面试的时间，显示剩余时间

### 注意事项
1. 当前实现已经大幅改善性能，进一步优化需要权衡复杂度
2. Streamlit 的架构限制了完全避免 `st.rerun()`
3. 批量模式下保存所有报告到 `all_reports`，方便后续对比分析
